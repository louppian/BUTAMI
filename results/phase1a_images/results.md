# Phase 1a. 사람 이미지 세 종류 수집

## 목적과 입력·출력

일반 안경 착용, 안경 미착용, 스마트글래스 착용 사람 이미지를 각 500장, 총 1,500장 목표로 수집한다.

- 새로 수집: `code/phase1a_images/recollect_images.py`
- 중단 후 이어받기: `code/phase1a_images/image_crawl.py`
- 원본: `data/images/no_glasses/`, `data/images/regular_glasses/`, `data/images/smart_glasses/`
- 출처·수집 기록: `results/phase1a_images/metadata.csv`
- 다음 단계: `code/phase2a_extract/extract_bbox.py`에서 얼굴·안경 bbox를 생성한다.

## 실행 준비

Python 3.12 환경에 `ddgs`, `requests`, `Pillow`, `torch`, `transformers`, `ImageHash`를 준비하고 IDE에서 파일을 실행한다. 목표 수량·배치 크기·다운로드 스레드 수는 파일 상단의 `TARGET=500`, `BATCH_SIZE=32`, `WORKERS=8`에서 수정한다.

CLIP은 `openai/clip-vit-base-patch32`를 사용하며 가중치를 `ckpt/pretrained/clip/`에 캐시한다. CUDA가 있으면 혼합 정밀도로 처리하고, 그 외에는 CPU를 사용한다.

기존 제품 수집 데이터는 별도로 보관한 후 사람 이미지 수집을 시작한다. 수집기는 `metadata.csv`의 `collection=people`과 이미지별 기록을 확인한다. 기존 제품용 CSV나 수집 기록 없는 JPEG가 있으면 해당 경로를 알리고 종료해 데이터 혼합을 방지한다.

## 이미지부터 다시 수집

`recollect_images.py`를 실행하면 세 클래스 폴더의 기존 데이터, `metadata.csv`, 기존 `face_glasses.json`을 `data/archive/people_<실행시각>/`에 원래 상대 경로 구조로 백업한 뒤 새로 수집한다. 모델 가중치·작업 문서와 폴더의 `.gitkeep`은 유지한다.

이 진입점은 실행할 때마다 새 수집을 시작한다. 중단한 수집을 이어갈 때는 `image_crawl.py`를 실행한다. 재수집 후에는 2a를 다시 실행해 새 이미지의 bbox JSON을 생성하고, 검수 후 3a를 실행한다.

## 수집 흐름

1. 한국어 검색어를 먼저 탐색한 뒤 영어 검색어를 탐색한다. 안경 미착용 24개(한국어 12·영어 12), 일반 안경 착용 28개(한국어 12·영어 16), 스마트글래스 착용 40개(한국어 20·영어 20)로 총 92개 검색어를 사용한다. 안경 미착용·일반 안경 착용은 사람·얼굴·안경테 검색어를, 스마트글래스 착용은 제품명·착용샷·착용 후기 검색어를 함께 사용한다. 검색어에 콜라주·일러스트·캐릭터·렌더·합성 제외 단어도 붙인다. 검색어마다 최대 5페이지, 페이지당 최대 100개 후보를 탐색한다.
2. 이미지 URL 중복을 제거하고 8개 스레드가 연결을 재사용해 후보를 다운로드한다. 요청 실패, 손상 이미지, 20MB 초과 파일, 짧은 변 256px 미만, 2,000만 화소 초과 이미지는 제외한다. EXIF 방향을 반영하고 RGB로 변환한다.
3. 전체 클래스의 기존 이미지와 현재 배치에서 pHash 해밍 거리 4 이하의 유사 중복을 제거한다.
4. CLIP은 세 종류의 사람 설명과 제품 단독 사진·여러 사람·콜라주·광고·부분 사진·무관한 사진 설명을 비교한다. 요청 클래스의 설명이 가장 높고 설명 간 softmax 점수가 0.7 이상일 때만 저장한다. 세 채택 설명은 얼굴이 보이는 실제 인물 사진으로 지정하고, 그림·캐릭터·CG 인물·얼굴 지움 편집·착용자가 보이지 않는 1인칭 장면도 제외 설명으로 비교한다.
5. 텍스트 특징은 한 번 계산해 재사용하고, 이미지 특징은 최대 32장씩 계산한다. GPU 결과는 배치당 한 번 CPU로 가져온다.
6. 검색어별 저장량을 제한하고 각 클래스가 500장에 도달하면 수집을 종료한다. 검색 범위에서 부족한 클래스는 실제 확보 수량을 출력한다.

## 저장과 이어받기

원본은 클래스별 `no_glasses_000001.jpg`, `regular_glasses_000001.jpg`, `smart_glasses_000001.jpg` 형식의 RGB JPEG로 저장한다. 원본 해상도를 유지한다.

CSV 필드는 `path`, `label`, `query`, `image_url`, `source_url`, `title`, `phash`, `filter_score`, `collection`이다. `path`는 프로젝트 루트 기준 상대 경로이고 `collection`은 `people`이다. 저장할 때마다 CSV에 기록한다.

재실행 시 실제 JPEG와 수집 기록을 확인해 기존 수량·해시·URL을 재사용한다. 기존 사람 이미지와 CSV를 그대로 둔 채 실행하면 추가한 한국어·영어 검색어로 남은 수량을 수집하고 다음 파일 번호부터 저장한다.

## 검수

CLIP 점수는 설명 사이의 상대 점수다. 특히 일반 안경과 스마트글래스의 라벨은 제품 정보·출처와 실제 착용 상태를 함께 검수한다. 검수한 사람 이미지를 Phase 2a에 전달한다. 동일 인물·제품의 학습·검증·시험 분할도 검수 과정에서 관리한다.

이 문서는 구현된 절차를 기록한다. 실제 수집 수량은 실행 출력과 CSV에서 확인한다.
